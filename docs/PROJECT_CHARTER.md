# Project Charter：Agent-for-Agent

- 仓库：`yujian777555/agentfotagent`
- 建立日期：2026-10-23
- 状态：研究假设阶段；未宣称创新性或有效性已经成立
- 研究核心：演化计算（EC）与 LLM Agent 递归自我改进（RSI）

## 1. 研究问题

当 Agent 需要通过反复修改自身的提示词、工作流、工具策略或其他可演化组件来提升任务表现时，能否先让 Agent 从标准黑盒优化任务中学习/发现更有效的高层演化控制策略，再把这些策略迁移到 Agent 自进化任务，并利用后者的进化反馈继续改进演化控制？

## 2. 主假设

**H1 — Agent 辅助的演化机制发现：** Agent 对搜索轨迹的诊断，能够提出经严格评估后优于适当基线的演化控制机制，而不仅仅是提出代码或参数变化。

**H2 — 跨域迁移：** 在 MetaBox 数值优化任务上发现的高层控制策略，在未参与发现/选择的 Agent RSI 任务上仍能带来可重复的收益。

**H3 — 双向反馈增益：** 在 H2 成立的前提下，使用 Agent 进化轨迹反馈更新控制策略，相比单向迁移能产生额外且可重复的收益。

上述 H1/H2/H3 是待审计假设，不是已确认结论。每项假设都必须有明确的否证条件；如果证据不支持，应收缩或停止相应路线。

## 3. 暂定方法框架

### 阶段 A：Agent 辅助演化计算改进

- 使用 MetaBox-v2 或兼容基准评估标准优化问题。
- 记录种群多样性、进步趋势、停滞、算子表现等可观察状态。
- 让 Agent 提出受约束、可执行、可复现的控制策略修改。
- 与原始算法、经典自适应方法、相关 LLM 算法设计方法进行公平比较。
- 采用独立验证/测试问题，避免把搜索过程中的最好结果误当作泛化证据。

### 阶段 B：把控制知识迁移到 Agent RSI

- 明确可迁移对象是高层控制策略，而不是把数值向量算子直接套到提示词或工作流上。
- Agent 任务适配器负责候选生成、执行、评价和谱系记录。
- 在固定模型、任务环境和实验协议下比较基线、独立 Agent 演化与迁移方法。
- 首先验证迁移，不预设迁移必然成功。

### 阶段 C：双向反馈（条件性阶段）

- 只有阶段 B 得到可重复正向证据后才启动。
- 将 Agent 进化中的成功/失败模式转化为结构化证据，供阶段 A 改进控制策略。
- 通过消融实验判断反馈是否提供超出单向迁移的额外价值。
- 预先隔离测试任务；不允许用测试集反馈反复修改方法后仍将其称为独立测试。

## 4. 论文贡献候选（尚未确立）

1. 一种基于 Agent 轨迹诊断的状态依赖演化控制策略发现方法。
2. 一种把高层演化控制知识从 MetaBox 数值优化迁移到 Agent RSI 的方法与验证协议。
3. 一种由 Agent 进化反馈驱动的演化控制更新机制。

候选贡献只有在相关工作审查和实验结果支持后才能进入论文主张。单纯整合 MetaBox、LLM、NSGA-III 或现有 Agent 演化组件不构成充分创新。

## 5. 相关工作审查范围

至少覆盖 EoH、LLaMEA、LMCOEA、MetaBox-v2，以及 EvoAgent、ARTEMIS、AIDE²、MASS 等 Agent 演化/递归自我改进方向。应比较其研究对象、搜索空间、控制变量、反馈信号、选择机制、基准、预算、泛化设置和真实 LLM 证据。名称或摘要层面的粗略比较不足以完成新颖性判断。

## 6. 实验与报告最低要求

- 报告基线、任务划分、种子、指标、运行环境、失败和排除规则。
- 对随机性显著的任务使用多种子实验，并报告均值、离散程度及适当统计检验。
- 把模拟器结果与真实 LLM/工具环境结果分开报告。
- 固定主要比较的实验条件；若模型、提示词、工具或环境不同，明确标注。
- 记录 API 调用、Token、费用和失败率；真实 API 实验需先明确预算和授权。
- 报告完整实验结果，不只选择最有利的任务或种子。

## 7. 明确的非目标

- 不把“有限预算分配”本身设为核心创新。
- 不因复杂闭环看起来更先进就默认它优于单向迁移。
- 不在 H1/H2 的基础证据不足时直接扩展到完整 RSI 系统。
- 不把 MetaBox 本身当成研究贡献。
- 不在没有当前仓库代码和复现实验支撑时，宣称历史模块或结果已经验收。

## 8. 成功与停止标准

阶段成功标准应在每个实验计划中预注册或明确写出。若 Agent 辅助发现无法优于强基线，或跨域迁移在独立任务上不稳定，应先分析原因并考虑收缩主张；若双向反馈没有增量收益，则删除该部分，不以增加模块替代证据。
