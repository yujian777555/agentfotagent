# Research Decision Log

本文件只记录影响项目方向、实验解释或范围边界的决定。新证据出现时可以修订，但必须保留原决定及修订理由。

## D-001：演化计算是方法核心

- 日期：2026-10-23
- 决定：研究必须以演化计算机制为核心；Agent 是算法发现/诊断者，也是后续演化的对象。
- 理由：符合项目的研究定位与导师方向约束。
- 影响：不能把 EC 简化为不加分析的通用候选筛选器。

## D-002：采用两阶段研究顺序

- 日期：2026-10-23
- 决定：先研究 Agent 如何改进演化计算，再研究改进后的演化控制能否迁移到 Agent RSI。
- 理由：分别验证方法来源和目标场景，避免一开始就把复杂闭环作为不可拆解的整体。
- 影响：跨域迁移是核心验证门；双向反馈为条件性扩展。

## D-003：MetaBox 是实验基础设施，不是创新点

- 日期：2026-10-23
- 决定：MetaBox-v2 用于标准优化基准、算法接入和可比评估；Agent RSI 仍需独立的任务环境与适配器。
- 理由：基准平台本身不能代替算法贡献。
- 影响：必须明确 MetaBox 任务与 Agent 任务之间的控制策略接口。

## D-004：跨域迁移优先于完整闭环

- 日期：2026-10-23
- 决定：先验证高层、状态依赖演化控制策略能否从数值优化迁移到 Agent RSI；迁移证据不足时，不实现完整反馈闭环。
- 理由：两类搜索空间存在明显差异，迁移是关键且可否证的研究假设。
- 影响：需要独立留出任务、无迁移基线、消融和泛化分析。

## D-005：有限预算分配不作为核心创新

- 日期：2026-10-23
- 决定：不把“预算有限时如何分配候选评估”作为本项目主创新点。
- 理由：用户明确认为单独研究有限预算的必要性不足。
- 影响：预算控制仅作为实验公平性和运行约束，不主导论文叙事。

## D-006：真实 LLM API 实验需单独授权

- 日期：2026-10-23
- 决定：在明确实验范围、费用/Token 上限和单独授权之前，不发起真实 LLM API 调用。
- 理由：先完成研究假设、基线和实验协议审计，避免过早消耗费用或污染实验。
- 影响：当前优先使用代码审计、可复现实验设计和必要的本地模拟验证。

## D-007：远端仓库是当前事实基线

- 日期：2026-10-23
- 决定：当前 GitHub 远端只有初始提交和简短 README。过往对话中提到的本地实现、测试、NSGA-III、PEEM、PPEC 及历史进化统计，在重新导入并复核前均标记为“历史上下文/未在本远端复核”。
- 理由：避免将不同本地目录、历史版本或探索记录误当成当前仓库中的可复现证据。
- 影响：第一步是对账和恢复证据，而不是假定代码已经存在。

## D-008：先审计已有假设，再扩展算法

- 日期：2026-10-23
- 决定：先核对 Phase 0 基线/模拟器、H1/H2/H3 假设和正式多种子实验协议；在审计完成前不新增 NSGA-III 实现，也不启动真实 API 实验。
- 理由：先判断核心机制是否值得继续，避免用更多代码掩盖尚未验证的研究假设。
- 影响：下一阶段优先级见 [latest_plan.md](../planner/latest_plan.md)。


## D-009：H1 单独不构成新颖性主张；H2 是关键可否证门

- 日期：2026-10-23
- 决定：不把“Agent/LLM 根据演化轨迹诊断并在线改进演化算子”作为独立的新颖性主张。LLM4EO 已明确包含演化状态感知、停滞触发、算子分析与在线算子元演化；EoH、LLaMEA、LAOS、LMCOEA 也构成直接或相邻先例。
- 理由：泛化的“LLM 赋能演化计算”已经有直接相关工作，简单换基准或改写模块不足以支撑论文创新。
- 影响：H1 作为 Stage-A 来源域验证门；项目核心应检验从 MetaBox 数值优化发现的抽象控制策略是否能迁移到独立 Agent-RSI 任务。H3 只有 H2 通过后才启动。
- 证据：见 [机制级文献矩阵](LITERATURE_MATRIX.md) 与 [H1/H2/H3 审计方案](../plans/phase0_hypothesis_audit.md)。

## D-010：历史项目只作只读证据，不自动合并

- 日期：2026-10-23
- 决定：EvoController、EvoPareto-Agent、llm-agent-rsi-r12-audit 等仓库作为独立先前项目进行只读审查；不将其代码、测试结果或结论自动视为 agentfotagent 的实现或验证。
- 理由：这些项目的任务、评估对象和实验边界不同；EvoController 的 action-credit 负结果尤其不能直接否定 LLM 规则发现或跨域迁移。
- 影响：任何复用都需记录来源 commit、接口改动、验证命令和新实验；没有真实 LLM 结果的 Agent-genome 代码不得被表述为真实 RSI 证据。
- 证据：见 [P0-R1 证据对账](RECONCILIATION.md)。


## D-011：MetaBox 上的 Agent 辅助演化计算必须先通过更强近邻方法审查

- 日期：2026-10-23
- 决定：将 LAOS、LMCOEA 和 AwesomeDE 作为 H1 的直接近邻工作，不再把“LLM/Agent 观察搜索状态并改进算子/更新规则”视为潜在独立创新。
- 理由：LAOS 的摘要明确将优化状态放入 meta-prompt 来选择算子；LMCOEA 使用 LLM 元演化生成/更新受约束多目标 EA 的规则；AwesomeDE 也用 MetaBBO 元训练 LLM meta-optimizer 生成约束 EA 更新规则。
- 影响：H1 仍需在 MetaBox 上通过强基线证明来源域控制有效，但论文的主要差异候选转向 H2：经明确适配器把同一高层控制策略迁移到 Agent RSI，并用随机/打乱迁移、目标域调优和固定控制器做对照。H2 的新颖性仍未确认。
- 证据：见 [机制级文献矩阵](LITERATURE_MATRIX.md)；来源包括 [LAOS](https://doi.org/10.1145/3712256.3726450)、[LMCOEA](https://doi.org/10.1016/j.eswa.2026.131756) 和 [AwesomeDE](https://arxiv.org/abs/2509.13251)。


## D-012：通用双向闭环不是创新点

- 日期：2026-10-23
- 决定：不把“Agent 改进演化算法，再由演化算法改进 Agent，并形成反馈闭环”这一框架描述本身当作创新。
- 理由：Hyperagents 已让 meta-level 改进过程可编辑并报告跨域迁移；HGM、CoCoEvolve、RSI-Router 也覆盖后代生产力、历史反馈和递归演化。
- 影响：必须证明 MetaBox 来源域学到的同一个控制对象，经过明确映射后能在异质 Agent genotype 上产生额外收益。

## D-013：通用跨基准迁移和组件分解也不是充分创新

- 日期：2026-10-23
- 决定：不把通用/环境特定组件分解、跨 benchmark 迁移或仅添加适配器视为独立创新。
- 理由：Harmony Harness 已分解通用 harness 机制与基准特定适配，并报告跨基准迁移；LMCOEA/AwesomeDE 已覆盖 MetaBBO 上的跨问题规则生成。
- 影响：H2 需要一个非平凡的跨表示迁移机制，并与目标域直接调优、固定通用控制器、打乱映射和随机搜索比较。

## D-014：历史检索、反思和在线算子演化属于已有机制

- 日期：2026-10-23
- 决定：不把轨迹反思、历史 archive 检索、停滞触发的算子修改、Pareto 选择或在线候选验证单独宣称为新颖。
- 理由：这些机制已分别出现在 LLM4EO、LAOS、GEPA、CoCoEvolve、RSI-Router、DGM/HGM 等工作中。
- 影响：相关组件只可作为基线或方法子模块；论文贡献必须来自经过实验证明的迁移机制或其他更具体的差异。

## D-015：LAOS 与 LMCOEA 的正文/代码审查仍未完成

- 日期：2026-10-23
- 决定：本轮能核验 LAOS 的官方出版记录/摘要，以及 LMCOEA 的出版记录/摘要；其正文访问失败，且本轮未找到官方代码。
- 影响：相关工作审查仍是部分完成，不能宣称已完成穷尽性新颖性证明。需继续寻找作者稿、补充材料或官方代码；若无法获取，明确标注证据限制。


## D-016：LAOS 摘要和 LMCOEA 索引正文片段已进一步核验

- 日期：2026-10-23
- 决定：将 LAOS 的官方 GECCO 摘要信息细化为：状态输入包括优化进度、最佳适应度、种群多样性和算子信用分配；存在固定策略历史的离线经验层和执行中生成的在线经验层。LMCOEA 的 ScienceDirect 索引正文片段显示其采用双层 MetaBBO-EL、由 LLM 元优化器生成/更新受约束 EA 规则、RTO²H 提示框架，并在 18 个可扩展约束问题上评估。
- 证据边界：LAOS 完整论文和官方代码仍未取得；LMCOEA 完整 PDF 和官方代码仍不可访问。以上是官方会议摘要/出版记录及索引片段，不等于完整正文或代码审计。
- 影响：两者均构成强近邻；不得把其详细机制写成已经完整复现，也不得假定 AwesomeDE 与 LMCOEA 是完全相同或完全独立的论文。
