# Agent-for-Agent：Agent 与演化计算的双向赋能研究

本仓库用于长期维护一个以**演化计算为方法核心、LLM Agent 自进化为研究对象**的研究项目。目标是形成可复现、可否证、能够支撑学术论文的研究证据，而不是仅把已有模块拼接起来。

## 暂定研究主线

1. **Agent → 演化计算**：让 Agent 分析演化轨迹、诊断搜索行为并提出可验证的演化机制改进。
2. **演化计算 → Agent**：将经过独立验证的演化控制策略迁移到 Agent 的提示词、工作流、工具策略或其他可演化组件。
3. **可选的双向反馈**：在前两步被证实有效后，再研究 Agent 进化反馈能否进一步改进演化控制策略。

核心假设是：某些高层、状态依赖的演化控制知识可能跨越数值优化与 Agent 自进化两类任务迁移。该假设**尚未得到验证**，必须通过基线、留出任务和消融实验检验。

## 研究定位

- 演化计算必须是方法核心，不能只作为 Agent 的装饰性搜索器。
- MetaBox 是数值优化基准/实验平台，不是论文创新点本身。
- 优先验证跨域迁移是否成立；只有迁移有独立证据后，才投入完整双向闭环。
- 不把有限预算分配本身作为核心创新点。
- 对 EoH、LLaMEA、LMCOEA、EvoAgent、ARTEMIS 及 RSI 相关工作的重叠进行持续审查。
- 任何结果都必须区分真实 LLM 实验、模拟实验、单次探索和正式多种子实验。

## 研究纪律

1. 每一阶段先记录基线 commit，再开展修改。
2. 不把未复现的历史结果写成当前仓库的已验证结果。
3. 不在同一批任务上反复调参后，再把它们当作独立测试集。
4. 报告所有基线、种子、失败、评估次数和环境差异；不只报告最好结果。
5. 每个阶段以证据决定继续、修改或停止，不以工程投入多少决定是否继续。
